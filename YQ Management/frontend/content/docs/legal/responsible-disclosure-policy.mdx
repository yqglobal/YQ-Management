# 1. At a Glance

Qmova welcomes responsible security research.

If you discover a potential security vulnerability affecting Qmova, we encourage you to report it privately so we can investigate and resolve it before it can be exploited.

In return, we ask researchers to:

- act in good faith
- avoid harming customers
- avoid accessing data unnecessarily
- avoid disrupting our services
- keep vulnerabilities confidential until resolved
- comply with this Responsible Disclosure Policy

We believe responsible disclosure improves security for everyone.

---

# 2. Purpose

The purpose of this policy is to establish a clear and responsible process for reporting security vulnerabilities affecting Qmova.

This policy aims to:

- encourage responsible security research
- protect Customers and Users
- reduce security risks
- provide a coordinated disclosure process
- establish expectations for researchers and Qmova

This policy applies only to security vulnerabilities.

It does not apply to:

- product feature requests
- customer support
- billing issues
- documentation feedback
- abuse complaints
- legal requests

---

# 3. Scope

This policy applies to publicly accessible Qmova services, including:

- Qmova web application
- APIs
- authentication flows
- Workspace management
- Visit management
- Appointment scheduling
- Queue management
- QR Check-in
- public documentation
- publicly available infrastructure owned and operated by Qmova

The policy does not automatically extend to:

- customer-owned systems
- customer-managed infrastructure
- third-party providers
- third-party integrations
- customer-owned WhatsApp environments
- customer internal networks

Security issues affecting third-party products should be reported directly to the relevant vendor.

---

# 4. Our Commitment

If you report a vulnerability in accordance with this policy, Qmova will:

- acknowledge receipt of your report
- investigate the issue
- assess the severity
- communicate with you where appropriate
- work to remediate confirmed vulnerabilities
- keep reports confidential where appropriate

We appreciate responsible disclosure and constructive collaboration.

---

# 5. Safe Harbor

If your research complies with this policy, Qmova will generally consider your activities to be authorized security testing.

This means we will not intentionally pursue legal action against researchers acting:

- in good faith
- responsibly
- within the limits of this policy

To qualify for Safe Harbor you must:

- avoid harming Users
- avoid privacy violations
- avoid destroying information
- stop testing immediately after proving the vulnerability
- report the issue promptly
- avoid public disclosure until coordinated with Qmova

Safe Harbor does not apply if your activities:

- violate applicable law
- involve extortion
- involve ransomware
- intentionally disrupt services
- intentionally expose Customer information
- install malware
- compromise Customer systems
- attempt financial fraud
- exceed what is reasonably necessary to demonstrate the issue

Nothing in this policy limits rights that cannot legally be waived.

# 6. Reporting a Vulnerability

Please report vulnerabilities by email.

**Email**

security@qmova.com

Please use the subject:

> Responsible Disclosure Report

Where possible, encrypt sensitive reports using any public key published by Qmova.

If no public encryption key is available, send the report via email and avoid including unnecessary sensitive information.

# 7. What to Include

A good vulnerability report should include:

## Summary

A concise description of the issue.

## Affected Component

Examples:

- Authentication
- Visit API
- Queue
- QR Check-in
- Admin Dashboard
- Notifications

## Severity

Your estimated severity.

If unsure, simply explain the impact.

## Steps to Reproduce

Provide enough information for us to reproduce the issue.

Include:

- URLs
- HTTP requests
- screenshots
- videos
- API requests
- browser information
- versions

where appropriate.

## Impact

Explain:

- what could happen
- who is affected
- prerequisites
- likelihood
- worst-case scenario

## Proof of Concept

Include a proof of concept if available.

Please avoid accessing unnecessary Customer information while creating a proof of concept.
